## 摘要

终端交互程序通常将界面文案、模型回答、工具输出及 ANSI 控制序列混合到同一字节流，外部包装器难以可靠识别其语义来源。本文介绍基于 taekchef/codex-code-zh-cn v1.2.0 的本地修订项目 codex-zh-local。系统将翻译范围限制为 49 条记录、24 组确认提示，使用完整片段匹配保留动态字段，以已有空格补偿中英文显示宽度差异，并在空间不足时退回英文。运行时采用 Node.js 与 Python 标准库实现 POSIX PTY，非交互调用绕过翻译；安装器仅创建独立入口，并按所有权记录卸载。验证在无宿主机挂载、禁网、非 root、只读根文件系统的真实 Linux ARM64 容器内完成。58 项 Node 检查、6 项 Python 检查、词表校验、模拟 CLI 完整交互及安装卸载均通过，临时运行环境清理后的所列宿主机路径检查未发现变化。结果支持已测样例和策略的正确执行，但不证明 UI 与正文完全分离、所有 Codex 版本兼容或真实模型任务正确。

**关键词：**命令行本地化；中文提示；伪终端；ANSI；白名单；容器验证；可复现工程

## 1 引言

英文提示会增加中文用户理解操作状态和审批选项的负担。本项目围绕具体使用需求展开：翻译 Exploring、Explored、Run、Failed 等固定提示，同时保留命令、代码、路径、编号和许可范围。研究对象是已有 CLI 的外部包装器，而非修改官方界面渲染源码。

包装器能独立部署，却只能观察终端输出。若程序分别输出界面标签和正文中的相同单词，外部字节流没有必然存在的来源标记。因此，本项目不以“完整语义识别”作为可达目标，而以缩小匹配范围、保护常见结构、保持传输行为并公开残余误译作为设计约束。软件基于上游项目固定提交 d5c554a860ed22483a49c820283439c9eb23746e，保留 MIT 许可与上游署名 [1]。界面文案的开发对照基线为官方 Codex CLI 0.162.1。

本文记录三项工程贡献：完整白名单与布局退回策略；无原生 npm 依赖的 PTY 传输与独立入口管理；包含源码哈希、实际输出、隔离检查和清理结果的公开验证材料。没有进行使用者实验或量化生产力研究。

## 2 问题定义与验证目标

输入是 CLI 输出字节流及用户输入流。输出是在满足约束时替换固定英文片段的终端流。对不匹配的片段，系统保留原文；非交互模式启动官方程序并透传其标准输出、标准错误和退出状态。

设 x 是候选完整片段，W(x) 是系统采用的显示宽度估计函数，T(x) 是词表译文。当 W(T(x)) 超过当前可用列数时，需要额外空格 d。只有相邻的现有 ASCII 空格能够补偿 d，且期间没有妨碍处理的光标控制时才翻译；否则保留英文。此规则保护已识别片段的总列数，不代表对全部终端字体和 Unicode 组合的精确建模。

验证目标包括：固定提示可按词表翻译；动态字段保持值；常见代码和 JSON 样例保持原文；控制序列保持；无换行提示有限等待后输出；PTY 保留中文输入、尺寸、信号和退出状态；安装不替换官方入口；测试容器不挂载宿主目录或读取真实账户材料。具体检查与证据映射见附录 A。

## 3 方法与实现

### 3.1 单一生效词表

data/ui-translations-local.json 是唯一运行时加载的词表，包含 A～E 共 24 组、49 条记录。A 为动作状态，B 为错误和输出，C 为连接状态，D 为审批和交互提示，E 为上下文及快捷键。旧数据文件仅保留历史参考。

翻译以完整片段为单位，正则使用首尾锚点，并保留界面前缀、选项编号、键盘标记及省略号。数值占位字段保留原值，错误详情字段保留正文。检查程序验证英文键唯一、占位符一致和已确认组覆盖。中文用语参考 Oxford 官方公开英文释义，再按计算机界面场景适配 [5]；未取得《牛津高阶英汉双解词典》第10版完整英汉条目，不能声称逐条复核该版中文原文。

### 3.2 控制序列、宽度和缓冲

AnsiTokenizer 将可打印文本与控制序列分离；UiMatcher 处理完整候选片段；StreamTranslator 负责保护状态、空格补偿和输出。明显代码、JSON 及围栏代码使用启发式保护。SGR 样式可以穿过待定标签，光标控制则使待定翻译退回原文。

刷新间隔配置为 25 ms；待输出内容在下一次定时回调中释放，避免长期扣留末尾文本。该值是调度参数，不是测得的最坏端到端时延保证：事件循环拥塞和操作系统调度可能造成延后。较大连续输出设有缓冲阈值。验证包括真实定时器释放无换行提示，以及 256 KiB 输出不截断等样例，但未进行性能基准或统计时延实验。

### 3.3 PTY 与非交互旁路

Node 包装器通过独立控制通道与 Python 辅助进程交互。Python 使用 POSIX 伪终端和标准库建立实际终端会话，并处理尺寸变化、信号、退出状态及输出排空。UTF-8 分块处理避免中文字符跨读取边界时损坏。Python 官方说明 PTY 是 Unix 功能且具有平台差异 [2]，因此本版范围限于 macOS/Linux，不沿用上游 Windows 支持声明。

exec、review、协议服务、帮助、版本及重定向调用绕过额外 PTY 与翻译。这样可以维持面向程序消费的 JSON、stderr 和退出码。旁路样例及官方 0.162.1 帮助/版本比较已执行；不存在对所有可能参数组合的穷尽证明。

### 3.4 独立入口与卸载归属

安装器仅创建 codex-zh-local 与 codex-zh-local-doctor，记录项目生成入口的所有权。卸载仅删除仍符合记录的入口；用户替换的入口保留。原官方 codex 及其配置、认证和会话文件不由包装器改写。配置覆盖和命令接管相关历史 API 已禁用。包装器自身语言设置保存在独立目录。

运行时没有 npm 依赖，不执行安装时网络下载或原生扩展编译。容器基础镜像及 Python 的准备仍需下载外部运行依赖，不能把“无 npm 依赖”扩展为整个测试供应链没有外部依赖。

## 4 实验设置

### 4.1 环境和源文件身份

宿主机为 macOS ARM64；临时 Lima 2.2.1 VZ 虚拟机使用 Ubuntu 24.04 ARM64。VM 分配 2 CPU、2 GiB 内存、12 GiB 稀疏磁盘，关闭共享目录、SSH agent 和端口转发。VM 就绪并验证隔离后，再单独安装 Docker 与 Python，避免慢速安装超出启动就绪等待。

实际被测容器使用 Node.js 24.21.0、Python 3.11.2。构建上下文严格限定 42 个文件，拒绝文件和父目录符号链接并固定归档元数据。公开 context-manifest.json 记录每个文件的 SHA-256；source-context.tar 保存当次输入，其 SHA-256 为 cf8d06f95bc0e70e162d16ffaf9fdd2a682e71a825d4ad5913a6226a3c2c533a。公开脚本可检查归档和当前被测源文件一致。

镜像 ID 为 sha256:500df018a0e5a85eb45225f91a043c718b5e3525f417593c7d88ba912be394a0。记录该 ID 用于标识当次结果，不表示能够下载已删除的本地镜像，也不保证从浮动基础镜像标签重新构建得到相同镜像。

### 4.2 容器隔离

Docker 创建策略为禁网、无宿主机挂载、UID/GID 1000、只读根文件系统、全部 capabilities 删除和 no-new-privileges。临时写入使用 256 MiB tmpfs；限制为 2 CPU、512 MiB 内存、256 个进程。启动前检查 Docker 配置，启动后检查 UID、网络接口、根文件系统、能力和 NoNewPrivs。

构建阶段下载运行依赖；测试执行阶段禁网。容器隔离减少测试代码接触宿主数据的机会，但依赖宿主虚拟化、Docker 及内核正确性，不能作为零风险承诺。Docker 官方文档描述相应权限、挂载和资源机制 [3]。

### 4.3 检查集和过程

Node 检查由内置 test runner 执行 [4]，覆盖匹配、控制序列、显示宽度、定时刷新、旁路、语言切换、入口归属和实际 PTY。Python 的 6 项容器检查覆盖上下文过滤、符号链接拒绝、策略允许/拒绝、失败清理和构建日志保留。另有 5 项临时运行生命周期检查在本机执行，不能计入容器内 6 项。

完整前端样例建立真实外层终端，再经过 Node 包装器、Python PTY 和模拟 CLI，检验中文标签和输入、UTF-8 分块、代码/JSON、选项编号与按键及退出码 17。shell 安装/卸载实际运行，但使用临时目录与合成官方 CLI、配置、认证和 profile。测试没有使用真实 Codex 账户或调用模型。

宿主机运行前备份指定配置，仅对认证文件记录哈希；运行结束后比较所列配置、官方入口及运行环境路径。公开材料只包含比较结论，不包含私密备份、认证文件内容或认证哈希。

## 6 讨论与有效性限制

白名单缩小翻译范围，但并未恢复输出的语义来源。正文独立输出 Working 等完整词条仍可能被翻译；启发式代码保护也可能漏掉不具备典型结构的代码。这是选用外部包装器的结构性限制。若需要强语义保证，应在官方渲染层接入本地化，属于不同实现路线。

短标签借用既有空格可能降低标签与命令间的视觉间距；空间不足时保留英文，不能承诺所有已收录词条总是中文显示。字体宽度、复杂 emoji、组合字符及新版重绘方式仍需实际终端检查。当前样例只支持已测结构的行为。

单次最终容器运行和有限测试集不能证明生产级安全性或全部版本兼容。没有测量用户理解准确率、误译概率、任务成功率或性能收益，也没有做随机化研究、渗透测试或全磁盘审计。真实模型任务和完整工具审批尚未验证。公开日志经过明确的路径脱敏，完整私密原件保留在维护者本机。

版本与哈希固定了已测源码，但基础镜像标签和发行版软件源可能改变。其他架构和未来依赖版本的复现结果应单独报告，而不是沿用本次计数。

## 7 结论

本项目在接受语义来源不确定性的前提下，实现了范围明确的中文提示包装器，并提供真实容器验证及清理检查材料。固定词表、旁路、宽度退回和入口归属降低了已识别风险；58 项 Node 与 6 项 Python 容器检查及端到端模拟样例支持这些具体实现的验证结论。后续工作包括真实官方 CLI 场景检查、跨版本终端回归、译法复核及语义渲染层本地化探索。
